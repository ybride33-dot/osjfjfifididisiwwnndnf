# Experimental local array-request composer

This is a small NumPy-trained four-head classifier, not a general coding model. It predicts one sign filter, one parity filter, one transform and one reducer from Korean requests. `coding-engine.js` then renders and interprets a fixed set of safe bounded operations. It does not execute model output or arbitrary user code. Input filtering and 0.8 minimum head probability may reject valid requests and cannot guarantee correctness; high-confidence errors have occurred. Examples exercise only a bounded 1,040-program search and may match an unintended operation.

Usage: `자비스 코딩 연습 <숫자 배열 요청>`; add ` | [{"input":[-2,2,4],"output":20},{"input":[2,3],"output":4}]` for example checks. `자비스 코딩 연습 보고` shows measurements. First use downloads composer-weights.json; the service worker may cache it for offline use. Input arrays: at most 100 safe integers, each -1000 to 1000; intermediate integer overflow is rejected.

Training: `OPENBLAS_NUM_THREADS=1 python3 tools/train_composer_model.py --steps 6000`, then `node tools/evaluate-composer.js`. Synthetic train, validation and test split operation combinations, but share expression patterns; the synthetic test set has been examined in development. `training/composer-final-probes.json` was written after choosing the confidence threshold; 20 handwritten probes are too few to establish real-world reliability. Evaluation runs separately through JavaScript with support checks. Reproducible checks: `node tests/composer-model.test.js`, `node tests/composer-functional.test.js`, `OPENBLAS_NUM_THREADS=1 python3 tests/composer-metrics.test.py`. Run browser tests with Playwright and Chromium installed. No actual Galaxy A17 device test has been performed.
